# AI 错误处理与降级策略文档

> 文档版本：v1.0 ｜ 更新日期：2026-08-04
> 目标：定义 AI 功能在各类异常下的行为、降级链路与用户提示，保证产品可用性下限。

---

## 1. 错误场景清单

| # | 场景 | 触发条件 | 当前行为（代码现状） | 建议行为 |
|---|------|---------|---------------------|---------|
| 1 | 未配置 Key | `DEEPSEEK_API_KEY` 为空 | 曾回退硬编码 Key（已修复，现应直接报错） | 返回明确错误：未配置 DEEPSEEK_API_KEY |
| 2 | 内容为空 | 用户未输入内容 | 400：请输入要排版的文章内容（已有） | 保持 + 前端前置校验 |
| 3 | DeepSeek 4xx | Key 失效/余额不足/限流 | 500：DeepSeek API 请求失败 (status) | 区分 401/429：提示检查密钥/稍后重试 |
| 4 | DeepSeek 5xx | 服务端故障 | 同上 500 | 重试 1 次（退避 1s）后降级 |
| 5 | 网络超时 | 前端 fetch 超时（默认无超时） | 一直等待，体验差 | 前端加 30s 超时 + 取消提示 |
| 6 | 返回非法 JSON | 网关异常 | res.json() 抛错 → 客户端 success:false | 服务端先校验 Content-Type，包装友好错误 |
| 7 | 输出截断 | 长文超出 max_tokens | 直接使用截断内容，结构可能残缺 | 检测 finish_reason，提示内容过长建议分篇 |
| 8 | 模型返回空 | 空字符串 | 回退原文（已有） | 保持，并提示 AI 未返回排版结果 |
| 9 | 客户端异常 | fetch 失败/解析失败 | catch → success:false + console.error | 保持 + UI 提示 |

## 2. 降级链路设计（建议）

```
用户点击「AI 结构化排版」
   │
   ├─► 前端校验（内容非空、长度限制）
   │
   ├─► 调用 /api/ai/layout-agent
   │      ├─ 成功 ──► 展示排版结果 + 排版建议
   │      ├─ 失败（网络/5xx）
   │      │      └─ 自动重试 1 次（指数退避 1s）
   │      │            ├─ 成功 ──► 展示结果
   │      │            └─ 失败 ──► 降级到本地规则排版
   │      └─ 失败（4xx：Key 无效/余额不足）
   │             └─ 不重试，直接提示用户检查配置
   │
   └─► 本地规则兜底（Markdown 启发式）
         - 按空行分段落、识别连续"一、二、三"为标题
         - 无 AI 时仍可用，保证产品可用性下限
         - 输出标注「已使用基础排版模式」
```

## 3. 用户提示文案规范（建议）

| 场景 | 文案（示例） |
|------|-------------|
| 内容为空 | 请先输入或粘贴要排版的文章内容 |
| Key 未配置 | AI 服务未配置，请联系管理员检查 DEEPSEEK_API_KEY |
| Key 失效/余额不足 | AI 服务暂时不可用（授权或额度问题），请稍后重试 |
| 服务繁忙/超时 | AI 服务繁忙，已自动重试；仍失败可稍后再试 |
| 已降级为基础排版 | AI 暂不可用，已用基础排版模式处理，样式可能较简单 |
| 输出疑似截断 | 文章较长，AI 输出可能不完整，建议分篇排版 |

要求：所有提示**告知状态 + 原因 + 下一步**，不使用纯技术错误码。

## 4. 可观测性（建议）

- 服务端日志：记录 status_code、耗时、finish_reason、模型名（**不记录文章全文**，仅记录长度）
- 错误码建议：
  - `AI_NOT_CONFIGURED`（未配置 Key）
  - `AI_AUTH_FAILED`（401）
  - `AI_RATE_LIMITED`（429）
  - `AI_UPSTREAM_ERROR`（5xx）
  - `AI_TIMEOUT`（超时）
  - `AI_TRUNCATED`（截断，可在响应中加 warning 字段）
- 前端：统计 AI 调用失败率、降级率、平均耗时（埋点，见评测文档）

## 5. 当前实现要点（代码事实）

- 前端：`src/services/aiLayoutAgent.ts` 统一 try/catch，任何异常返回 `{ success: false, error }`，UI 层负责展示
- 服务端：`server.ts` 的 `/api/ai/layout-agent` 返回 `{ success, result, summary, layoutSuggestion }`；异常返回 `500 { success: false, error }`
- 空内容：`400 { success: false, error: '请输入要排版的文章内容' }`
- 无超时、无重试、无截断检测、无本地降级——均为待建设项
