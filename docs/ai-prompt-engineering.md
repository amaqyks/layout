## 1. 功能架构

```
┌─────────────┐   POST /api/ai/layout-agent   ┌──────────────────┐   OpenAI 兼容   ┌─────────────┐
│ 前端编辑器   │ ────────────────────────────► │  server.ts 服务端  │ ─────────────► │ DeepSeek API │
│ aiLayoutAgent│ ◄──────────────────────────── │  (提示词在此维护)  │ ◄───────────── │  deepseek-chat│
└─────────────┘        JSON 响应               └──────────────────┘                └─────────────┘
```

- 前端入口：`src/services/aiLayoutAgent.ts` 的 `runAILayoutAgent(rawContent, articleTitle, styleConfig)`
- 服务端接口：`POST /api/ai/layout-agent`（`server.ts`）
- 提示词维护位置：`server.ts` 内联（前端注释已说明提示词由服务端统一管理，避免双份不一致）

## 2. 模型与参数（当前值）

| 参数 | 当前值 | 说明 |
|------|--------|------|
| 模型 | `deepseek-chat` | DeepSeek 对话模型 |
| 接口 | `{DEEPSEEK_API_BASE}/v1/chat/completions` | 默认 `https://api.deepseek.com` |
| temperature | 0.6 | 结构性任务，建议保持 ≤0.7 |
| 请求头 | `Authorization: Bearer {DEEPSEEK_API_KEY}` | Key 来自 `.env`（禁止硬编码，见安全章节） |

## 3. 系统提示词设计解析

系统提示词共 7 个模块，目标明确：**内容一字不改，只做结构重组**。

### 3.1 角色与任务

> 你是一位顶级微信公众号排版专家。你的唯一任务是——为用户的原始文本添加排版结构标记。内容一字不改，只做结构重组。

设计要点：单一任务声明 + 强约束（一字不改），防止模型改写内容。

### 3.2 核心理念

> 排版是为内容服务的。克制与合理结构比视觉花哨更重要。目标：手机端阅读体验流畅、视觉层次清晰、读者能快速抓住重点。

作用：给模型一个价值判断标准，避免过度美化。

### 3.3 铁律（绝对禁止）

1. 严禁增删改用户原文的任何字、词、句
2. 严禁添加原文中不存在的观点、事实或结论
3. 只能添加 Markdown 结构标记（`#`、`##`、`###`、`**`、`>`、`---`、`-` 列表等）

### 3.4 排版转换规则（5 条）

| 规则 | 内容 | 对应渲染 |
|------|------|---------|
| 1. 标题保留序号与标点 | `#` 大标题、`##` 章节、`###` 小标题；必须保留原文数字/序号/括号/点号（"一、"、"1."、"①"） | 标题层级 |
| 2. 引言与引用块 | 开篇总结段/金句用 `> **「金句标题」**——内容`；示例案例整段引用 | blockquote |
| 3. 章节分割线 | 每个 `##` 上方加 `--- ` | 分割线 |
| 4. 观点句加粗 | 章节首个核心结论句整句加粗（10-30 字）；并列词汇加粗 | strong |
| 5. 并列项转列表 | 并列条目/步骤/选项转 `- ` 无序列表，关键词加粗 | ul + strong |

### 3.5 输出格式

- 直接输出带 Markdown 标记的完整正文
- 禁止包裹在代码块中，正文前后禁止任何解释/问候
- 提供完整「正文输出结构示例」（主标题 → 引言金句 → 分割线 → 章节 → 加粗结论 → 小标题 → 列表 → 结语）

### 3.6 用户提示词

```
文章标题：{title 或 '未命名文章'}

文章内容：
{content}
```

注意：请求体同时允许 `styleConfig`，但服务端当前**未使用**（见 §5 已知问题）。

## 4. 输出解析逻辑

服务端对模型返回做后处理：

1. `rawOutput = choices[0].message.content.trim()`；空时回退为原文
2. 用正则 `/\\n---\\s*\\n(> \\*\\*排版建议\\*\\*[\\s\\S]*)$/` 切分「正文」与「排版建议」
3. 响应：`{ success, result(正文), summary, layoutSuggestion(排版建议) }`

## 5. 已知问题与改进建议

| # | 问题 | 影响 | 建议 |
|---|------|------|------|
| 1 | `styleConfig` 传入但服务端未使用 | 模板样式无法指导 AI 排版决策 | 将模板配色/风格描述注入提示词 |
| 2 | 系统提示词内联在 `server.ts` | 无法版本化、无法 A/B | 提取为独立 `prompts/layout.md` 或配置项 |
| 3 | 无失败重试 | 偶发网络失败直接报错 | 增加 1 次指数退避重试 |
| 4 | 输出长度无上限控制 | 长文可能截断 | 增加 max_tokens 与截断检测 |
| 5 | 历史遗留：服务端曾硬编码 API Key | 密钥泄露风险 | 已修复 + 建议立即轮换 Key（见隐私文档） |
